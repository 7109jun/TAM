# Release Notes

TAM과 `tamc`의 변화를 버전 순서로 적는다. 호환성 약속은 [The TAM Reference 18장](reference.md#18-호환성-약속-tam-1)에 있다.

## 1.0.0

TAM의 **첫 공식 지원 버전**이다. 이 버전이 정의하는 언어가 **에디션 1**이며, 이후 `1.x` 컴파일러는 에디션 1로 쓴 올바른 프로그램을 같은 의미로 계속 컴파일한다.

### 추가된 것

- **`const`**: `const NAME: T = 식`. `T`는 정수, `f64`, `bool`, `str`. 컴파일 시간에 128비트로 계산하고 범위를 검사한다. 다른 상수와 `모듈::NAME`을 참조할 수 있고, `pub const`로 모듈 밖에 보이며, 배열 길이(`[T; N]`, `[v; N]`)에 쓴다. 순환 정의는 오류다.
- **`loop { }`**: `while true { }`와 같다. `break` 없는 `loop`로 끝나는 함수는 마지막 식이 필요 없다.
- **블록 주석** `/* */`: 중첩된다.
- **제네릭**: 함수, 구조체, `impl`. C++ 템플릿처럼 **단형화**하며, 쓰이는 인스턴스를 만들 때 본문을 검사한다. 트레이트와 경계는 없다. 타입 인자는 직접 적은 것 → 인자 타입 → 기대 타입 → 정수 리터럴 `i32` 순으로 정한다. 인스턴스 오류는 "while instantiating" 위치를 함께 보여 준다. 한도는 깊이 64, 인스턴스 5000개.
- **`edition`** 키: `Tmake.toml`의 `[package]`에서 `edition = "1"`(생략하면 `"1"`). 모르는 에디션은 `unsupported edition`으로 거절한다.
- **백엔드**: `llc`가 없으면 `clang -c`로 `.ll`을 오브젝트로 만든다. 공식 Windows LLVM 배포본에는 `llc.exe`가 없기 때문이다. `TAMC_BACKEND=clang`이면 강제한다.
- **문서**: The TAM Book(14장), TAM by Example, Standard Library API, Tmake.toml, The TAM Reference, 그리고 Why TAM, Safety and Memory Model, Compiler Architecture, Style Guide, 이 Release Notes. 모든 코드 예제는 `tamc`로 컴파일·실행해 검증한다.

### 확인한 것

- Windows용 `tamc.exe`를 GitHub Actions(`windows-latest`)에서 빌드하고, LLVM이 PATH에 없는 상태에서 묶인 `clang.exe`와 `lld-link.exe`만으로 `.exe`를 만들어 **실제 Windows에서 실행해 종료 코드 42를 확인했다**.
- 제네릭 퍼저 800개 프로그램이 파이썬 참조 구현과 일치했다. 기존 퍼저와 valgrind(제네릭 힙 포함)에서 추가 문제가 없었다.

### 알려진 한계

- 트레이트(경계), 메서드 자신의 타입 매개변수, 상수 제네릭이 없다. 쓰이지 않은 제네릭은 검사되지 않는다.
- 열거형, 튜플, 클로저, 연산자 오버로딩이 없고, `Vec`/해시맵 같은 컬렉션이 없다.
- 의존성은 경로(path)만 된다.
- 오류는 첫 번째 하나만 보고한다.
- 힙 필드를 `self.field`로 꺼내 이동할 수 없다(`T = String`인 인스턴스에도 적용).

전체 목록은 [Reference 17장](reference.md#17-아직-없는-것)에 있다.

### 업그레이드

첫 공식 버전이라 옮길 것은 없다. 1.0 이전에 쓰던 코드는 그대로 컴파일된다. 새로 생긴 키워드 `const`, `loop`는 1.0 이전에 식별자로 쓰던 이름이면 바꿔야 한다.

## 개발 이력 (1.0 이전)

공식 버전 전의 마일스톤이다. 각 마일스톤은 반드시 실제로 실행되는 상태로 끝났다.

| 마일스톤 | 내용 |
|---|---|
| M1 | 골격, Lexer, Parser, 진단(파일·줄·열 오류) |
| M2~M3 | 타입 검사, `.ll` 출력, 변수, 산술, `if`/`while`, 함수 호출 |
| M4 | `bool`, `f64`, 비교·논리 연산, 여러 정수형, `as` 변환 |
| M5 | `struct`, 참조 `&`, `&mut`, `*` |
| M6 | 소유권(이동) 검사 |
| M7 | 빌림 검사(가변/불변 충돌, 댕글링) |
| M8 | 모듈(`use`, `pub`), `unsafe`, raw 포인터 |
| M9 | `Result`, `?`, `match`, `str` 리터럴, 힙 `String`, 자동 해제 |
| M10 | Windows `.exe`: CRT·MSVC·SDK 없이 `kernel32` import lib을 직접 생성 |
| M11 | `extern` FFI, 표준 라이브러리 `tam.os`, `tam.fmt` |
| M12 | 펌웨어: UEFI, BIOS, AArch64 베어메탈(QEMU로 부팅 검증) |
| M13 | 비트 연산자, 배열·슬라이스, 메서드, `Option`, 오버플로·0 나눗셈 trap |
| M14 | 복합 대입, `for`/`break`/`continue`, 리터럴, `Option` 메서드, 패닉 메시지 |
| M15 | 스택 변수 → SSA 승격(`mem2reg`), 호스트 `-O2`, 큰 스택 프레임 링크 버그 수정 |
| M16 | `Tmake.toml`: 의존성, 프로파일, 워크스페이스, 잠금 파일, 증분 캐시 |
| M17 | 버그 사냥과 문서 5종 |
| M18 | `const`, `loop`, 블록 주석, 제네릭 → **1.0.0** |

### 퍼저와 검증이 찾은 대표적인 버그

- **컴파일러 스택 오버플로**(M17): 괄호 2만 겹, `1 + 1 + …` 2만 항, 블록 3천 겹 같은 입력에서 `tamc` 자체가 죽었다. 파서에 깊이 한도를 두고 위치와 함께 오류를 내게 했다.
- **큰 스택 프레임 링크 실패**(M15): 4KiB를 넘는 지역 배열이 있는 함수가 Windows/UEFI/BIOS/AArch64에서 링크에 실패했다. CRT가 없어서 `__chkstk`를 직접 제공해 해결했다.
- **최솟값 리터럴**(M14): `-128`(`i8`) 같은 리터럴이 부정 연산에서 오버플로 trap하던 문제.
- **UTF-8 BOM**(M17): Windows 편집기가 붙이는 BOM이 있는 파일이 거절되던 문제.
- **`&&` 토큰**(M17): `&&T`(타입)와 `&&x`(식)가 파싱되지 않던 문제.
- **의존성 순환**(M16): 감지되지 않던 문제.

## 앞으로

아래는 **계획이 아니라 후보**이며, 약속이 아니다. 모두 에디션 1의 기존 코드를 깨지 않는 **추가**로만 들어온다.

- 표준 라이브러리: 제네릭 `Vec<T>`
- 트레이트 경계(경계 없는 기존 제네릭은 계속 컴파일된다)
- 열거형과 `match` 확장
- 사용자 allocator 교체
- 레지스트리 의존성
- 여러 오류를 한 번에 보고
