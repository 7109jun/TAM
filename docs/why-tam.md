# Why TAM: 설계 철학과 비교

이 문서는 "TAM이 왜 이런 모양인가"와 "내 일에 TAM이 맞는가"에 답한다. 문법은 [The TAM Book](book/README.md), 정확한 규칙은 [The TAM Reference](reference.md)를 본다.

- 대상 버전: `tamc 1.0`
- 이 문서의 코드는 `tamc 1.0`으로 컴파일하고 실행해 검증했다.
- 비교 대상(C, Rust, Go, Zig)에 대한 서술은 각 언어의 **일반적인 특징**이며, TAM이 그들을 대체한다는 주장이 아니다.

## 1. 한 문장

> **사용자에게 통제권을 모두 준다. 안정성은 컴파일러가 책임진다.**

TAM은 C처럼 메모리와 하드웨어를 직접 다루면서, C가 프로그래머에게 맡기는 "실수하면 조용히 깨지는" 부분은 컴파일러가 대신 막는 시스템 프로그래밍 언어다. 런타임도, 가비지 컬렉터도, 숨은 할당도 없다.

## 2. 세 가지 기준

### 간결함

C보다 간결해야 한다. 그래서 TAM은 다음을 뺐다.

- 세미콜론(줄바꿈이 문장 끝), 함수 반환 화살표(`fn add(a: i32, b: i32) i32`), `let mut`(대신 `mut`).
- 헤더 파일과 전방 선언(함수는 정의 순서와 무관하게 보인다).
- lifetime 표기. 컴파일러가 추론하고, 모호하면 오류로 알려 준다.

```tam
// exit: 7
struct Point { x: i32, y: i32 }

impl Point {
    fn sum(&self) i32 { self.x + self.y }
}

fn main() i32 {
    let p = Point { x: 3, y: 4 }
    p.sum()
}
```

### 안정성

"안전한 코드에서는 메모리 오류가 생길 수 없다"가 목표다. 컴파일러가 다음을 책임진다.

| 오류 종류 | TAM의 처리 |
|---|---|
| 해제 후 사용, 이중 해제 | 소유권 검사로 컴파일 오류 |
| 누수 | 스코프 끝에서 자동 해제 |
| 댕글링 참조 | 빌림 검사로 컴파일 오류 |
| 배열 경계 밖 접근 | 실행 시 trap(조용히 깨지지 않는다) |
| 정수 오버플로, 0 나누기 | 실행 시 trap |
| 초기화되지 않은 변수 | 초기화 없는 선언 자체가 없다 |
| 널 포인터 | 안전한 참조는 널이 될 수 없고, 없을 수 있는 값은 `Option` |

자세한 보장과 한계는 [Safety and Memory Model](safety.md)에 적었다.

### 시스템 프로그래밍

한 컴파일러로 다음 대상을 만든다. OS도, C 런타임도 필요 없다.

| 대상 | 산출물 |
|---|---|
| `host` | Linux 네이티브 실행 파일 |
| `windows` | `kernel32`만 쓰는 x64 `.exe`(CRT, MSVC, SDK 불필요) |
| `uefi` | x86-64 UEFI 애플리케이션 |
| `bios` | x86-64 BIOS 부팅 디스크 이미지 |
| `aarch64` | AArch64 베어메탈 `Image` |

`unsafe` 블록 안에서는 raw 포인터, 직접 할당, MMIO와 포트 입출력을 쓸 수 있다. 통제권은 사용자에게 있다.

## 3. 핵심 결정과 이유

| 결정 | 이유 |
|---|---|
| 가비지 컬렉터 없음, 소유권 + 자동 해제 | 실행 시간 비용과 예측 불가능한 멈춤이 없다. 펌웨어에서도 같은 규칙이 돈다 |
| 예외 없음, `Result`/`Option` + `?` | 실패가 타입에 드러난다. 제어 흐름이 숨지 않는다 |
| 오버플로는 **언제나** trap(빌드 모드와 무관) | 디버그와 릴리스가 다르게 동작하지 않는다. 감싸는 산술은 `wrapping_add`로 명시한다 |
| 제네릭은 단형화, 트레이트 없음 | C++ 템플릿처럼 실행 비용이 없고 구현이 작다. 대신 오류는 쓸 때 나온다 |
| `Tmake.toml`은 표준 TOML | 독자 문법을 배우지 않는다 |
| 문법 호환성 약속(에디션 1) | 1.0으로 쓴 코드가 1.x에서 계속 돌아간다([Reference 18장](reference.md#18-호환성-약속-tam-1)) |
| 첫 오류만 보고 | 오류 폭주 없이 한 번에 하나를 고친다 |

## 4. 다른 언어와의 비교

한눈에 보는 표다. "있다/없다"는 이 문서 작성 시점의 `tamc 1.0` 기준이다.

| | C | Rust | Go | Zig | TAM |
|---|:-:|:-:|:-:|:-:|:-:|
| 가비지 컬렉터 없음 | ✔ | ✔ | ✘ | ✔ | ✔ |
| 컴파일 시간 메모리 안전(안전한 부분집합) | ✘ | ✔ | (GC로) | 일부 | ✔ |
| lifetime 표기 필요 | - | 자주 | - | - | **없음**(추론) |
| 제네릭 | 매크로 | 트레이트 경계 | 있음 | comptime | 단형화(경계 없음) |
| 트레이트/인터페이스 | ✘ | ✔ | ✔ | ✘ | **✘** |
| 열거형(enum), 클로저 | enum만 | ✔ | ✔ | ✔ | **✘** |
| 베어메탈(UEFI/BIOS) 내장 | 컴파일러 외 | 별도 타깃 | ✘ | ✔ | ✔ |
| 표준 라이브러리 | 큼 | 큼 | 큼 | 중간 | **아주 작음** |

- **Rust와 가장 가깝다.** 소유권, 빌림, `Result`, `?`가 같은 사상이다. 대신 lifetime 표기, 트레이트, 매크로를 뺐고, 그 만큼 표현력도 작다.
- **C의 자리를 노린다.** 크기가 작은 언어, 예측 가능한 코드 생성, 베어메탈 지원이 그렇다. 대신 안전한 부분에서는 정의되지 않은 동작이 없다.
- **Go와 다르다.** GC도 런타임도 없고, 동시성 모델도 없다.

## 5. 이 언어가 **아닌** 것

솔직한 한계도 설계의 일부다.

- **범용 애플리케이션 언어가 아니다.** 표준 라이브러리는 `tam.os`, `tam.fmt`, `tam.serial`뿐이다. `Vec`, 해시맵, 정규식, 네트워크는 없다.
- **트레이트, 열거형, 클로저, 튜플이 없다.** 큰 추상화에는 아직 불편하다.
- **스레드와 비동기가 없다.**
- **패키지 레지스트리가 없다.** 의존성은 경로(path)만 된다.
- **오류는 하나씩만 보고한다.**
- **보수적인 빌림 검사.** 안전하지만 드물게 올바른 코드를 거절한다([Reference 9장](reference.md#9-빌림-규칙)).

다음에 맞는다면 TAM이 어울린다: 작은 커널·부트로더·펌웨어, 런타임 없는 도구, 소유권을 배우며 컴파일러 구조를 보고 싶을 때. 큰 서비스를 빨리 만들어야 하면 지금은 다른 언어가 낫다.

## 6. C와 Rust 사용자를 위한 번역

### C에서

| C | TAM |
|---|---|
| `int add(int a, int b) { return a + b; }` | `fn add(a: i32, b: i32) i32 { a + b }` |
| `int x = 5;` / `const int y = 5;` | `mut x = 5` / `let y = 5` |
| `#define N 8` | `const N: i32 = 8` |
| `for (int i = 0; i < n; i++)` | `for i in 0..n` |
| `while (1) { ... break; }` | `loop { ... break }` |
| `int a[4] = {0};` | `let a = [0; 4]` |
| `malloc`/`free` | `String`은 자동. 직접은 `unsafe { alloc(n) }`/`free(p)` |
| `NULL` 반환으로 실패 알림 | `Option<T>` / `Result<T, E>` |
| `errno` 확인 | `match`나 `?` |
| `assert(x)` | `assert(x)`(실패하면 trap) |

```tam
// exit: 10
const N: i32 = 5

fn sum_to(n: i32) i32 {
    mut s = 0
    for i in 1..=n { s += i }
    s
}

fn main() i32 {
    sum_to(N) - 5
}
```

### Rust에서

| Rust | TAM |
|---|---|
| `fn f(x: i32) -> i32` | `fn f(x: i32) i32` |
| `let mut x = 0;` | `mut x = 0` |
| `fn first<'a>(a: &'a [i32]) -> &'a i32` | `fn first(a: &[i32]) &i32`(추론) |
| `enum Option<T>` / `Result<T, E>` | 내장 `Option<T>` / `Result<T, E>`(직접 만들 수는 없다) |
| `impl<T> Pair<T>` | `impl Pair<T>` |
| `trait`, `where T: Ord` | 없음. 본문을 인스턴스화할 때 검사한다 |
| `match`가 모든 경우를 다룬다 | `Ok/Err`, `Some/None`만 |
| `Box<T>`, `Vec<T>` | 없음(`unsafe`로 직접 만든다) |
| `.map(\|x\| ...)` | 없음(클로저가 없다) |

```tam
// exit: 6
fn first(a: &[i32]) &i32 { &a[0] }          // lifetime 표기 없이 컴파일된다

fn main() i32 {
    let a = [6, 7, 8]
    *first(&a)
}
```
